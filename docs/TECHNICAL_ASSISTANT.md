# Технический ИИ-ассистент

Read-only анализ инструмента по тикеру: много-TF история, уровни, зеркалки, объёмы, сценарии пробой/отскок. **Не торгует** и не меняет config.

## Dashboard

Вкладка **«Ассистент»** (`http://127.0.0.1:9020/dashboard/#assistant` или `https://gateway.24alert.ru:8080/dashboard/#assistant`):

**Nginx:** на `gateway.24alert.ru` нужен `location /assistant` → `:9020` (см. `deployments/nginx-assistant-location.snippet`, скрипт `deployments/patch-nginx-assistant.sh`). Без этого UI покажет `404 Not Found nginx`.

1. Выберите тикер (каталог MOEX).
2. **Анализировать** — async job 30–90 с.
3. График `1d | 1h | 5m`, панель уровней (accordion), блок сценариев.

## API (strategy-runner :9020)

| Method | Path | Body / query |
|--------|------|----------------|
| POST | `/assistant/analyses` | `{"ticker":"NGM6"}` → `202` `{analysis_id, status, ticker}` |
| GET | `/assistant/analyses/{id}` | полный результат или `running` + `progress_pct` |
| GET | `/assistant/analyses/{id}/chart?tf=1h` | свечи + уровни для TF |
| DELETE | `/assistant/analyses/{id}` | удалить из кэша (TTL 24h) |

### Правила построения уровней

Цель — **не больше ~18 зон в списке** и **8 линий на графике 5m** у текущей цены. Раньше каждый часовой свинг с одним касанием давал отдельную «зеркалку» — десятки линий в копейках друг от друга.

#### 1. Структурные экстремумы

| Источник | Окно | Что берём |
|----------|------|-----------|
| Daily | год (`1d`, ~365 баров) | **2** максимума + **2** минимума (сильнейшие по рангу) |
| Hourly | ~5 торговых дней на `1h` | **2** high + **2** low |
| POC | объём по цене | по одной зоне на **5m** (неделя) и **1h** (месяц) |

#### 2. Зеркальные уровни

На `1h` (fallback — `1d`, если мало баров):

1. Свинги: локальные high/low с **крылом 5** баров (меньше шума, чем wing=3).
2. **Кластеризация** свингов в одну цену, если расстояние ≤ **0,25%** от текущей цены (для цен &lt; 50 — **0,4%**).
3. Кандидат в зеркало только если за историей:
   - **≥ 2** реакции как поддержка **и** **≥ 2** как сопротивление;
   - суммарно **≥ 5** реакций (пересечения close + отскоки телом свечи).
4. В итог попадают **не более 5** зеркал с наибольшим числом реакций.

#### 3. Слияние и отбор

1. Точные дубликаты (цена + kind) убираются при merge.
2. Все уровни **кластеризуются** в зоны (тот же порог ~0,25%): усредняется цена, берётся max сила/касания/объём.
3. Сортировка по силе (1–5), затем **cap 18**: уровни дальше **12%** от цены отбрасываются, кроме сильных daily (strength ≥ 5).
4. ID **L1…Ln** после финальной сортировки.

#### 4. Что рисуется на графиках

Отдельно от полного списка — фильтр по TF и дистанции от **последней цены** (5m):

| TF | Макс. линий | Дистанция от цены | Состав |
|----|-------------|-------------------|--------|
| **1d** | 10 | зеркала ≤ 20% | daily + близкие зеркала |
| **1h** | 10 | зеркала ≤ 6% | hourly, POC 1h, близкие зеркала |
| **5m** | 8 | **≤ 1,8%** | любые уровни в коридоре у цены |

#### 5. Метрики уровня

После отбора: касания и объём в зоне по **1h** (или 5m), средняя реакция в bps, `volume_note` для accordion.

**LLM** дополняет `report_md` по каждому уровню и 2+ сценария (`bounce`, `breakout`, `range`); на количество уровней не влияет.

Реализация: `assistant_levels.go`, `assistant_mirror.go`, `assistant_level_rules.go`.

## Переменные окружения

| Env | Default | Описание |
|-----|---------|----------|
| `ASSISTANT_ENABLED` | `true` | `false` — API отклоняет новые анализы |
| `ASSISTANT_MODEL` | `AI_CHAT_MODEL` или Claude Sonnet | OpenRouter model |
| `ASSISTANT_MODEL_FALLBACKS` | — | запасные модели через запятую |
| `OPENROUTER_API_KEY` | — | обязателен для LLM-отчётов (иначе fallback) |
