# Инструкция для техлида: Review DevOps TASK-001

## Что проверить

При review `devops/handoff.md` убедитесь в следующем:

### 1. ✓ SSH доступ и безопасность
- [ ] Подключение адреса 176.123.160.234 и пользователя adm-srv03-cloud прошло успешно
- [ ] SSH ключ авторизован правильно
- [ ] Sudo доступ включен (NOPASSWD: ALL) — это риск? Нужно ли ограничить?

### 2. ✓ Ресурсы достаточны?
- [ ] 2 CPU — хватит ли для production? Или нужны мощнее?
- [ ] 3.8 GB RAM — хватит ли? Есть ли лимиты памяти для контейнеров?
- [ ] 24 GB свободного диска — хватит ли? Или нужно расширить?

### 3. ⚠️ Docker НЕ установлен
- [ ] Одобрить установку Docker перед deployment?
- [ ] Версия Docker — какую выбрать (latest, LTS, specific)?
- [ ] Есть ли требования к версии Docker для platform?

### 4. 🔧 Недостающие инструменты
- [ ] jq требуется? Установить?
- [ ] kubectl требуется для k8s? Или не нужен?

### 5. 🛡️ Безопасность
- [ ] Sudo без пароля — это приемлемо? Ограничить команды?
- [ ] SSH log показывает попытки bruteforce (Nov 08) — нужно ли усилить security?
- [ ] Firewall настроен правильно? Открыт ли только SSH (22)?

### 6. 📊 Логирование и мониторинг
- [ ] Журналы системы чистые? PCI ошибки не критичны?
- [ ] NTP синхронизирован — хорошо
- [ ] Нужен ли setup мониторинга (Prometheus/Grafana)?

## Действия техлида

### Если все хорошо ✅
```
1. Создать handoff.md в tech-lead/ папке
2. Написать APPROVAL
3. Передать пользователю / plannerу для обновления prompts для фронтенда и бэкенда
```

### Если есть замечания ⚠️
```
1. Написать замечания в handoff.md (раздел "Замечания техлида")
2. Вернуть на DevOps для корректировки
   Пример: "Требуется увеличить объем диска до 100 GB"
3. DevOps обновляет handoff.md и повторно передает на review
```

### Если критический дефект ❌
```
1. Написать замечания в handoff.md
2. Передать пользователю (BLOCKED)
   Пример: "Docker обязателен, требуется переустановка сервера"
```
