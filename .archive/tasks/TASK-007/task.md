# TASK-007: Закрытие портов микросервисов наружу

## Зачем

Сейчас все внутренние микросервисы (order-svc :9001, marketdata-svc :9002, portfolio-svc :9003, risk-svc :9004) и Prometheus (9090) биндятся на **`0.0.0.0`**, то есть доступны из интернета напрямую. Это критическая уязвимость:

- Любой, кто узнает IP сервера, может обратиться к `176.123.160.234:9001` и работать с ордерами напрямую, минуя gateway
- Prometheus на `:9090` может раскрывать внутреннюю структуру системы
- Единственная защита сейчас — firewall Timeweb, который ненадёжен

## Цель

Сделать так, чтобы все внутренние сервисы были доступны **только** через `127.0.0.1` (loopback), а наружу — только gateway (`:8080`) через nginx.

## DoD (Definition of Done)

- [ ] Все микросервисы bind на `127.0.0.1` вместо `0.0.0.0`
- [ ] Gateway остаётся на `127.0.0.1:18080` (через nginx)
- [ ] Prometheus доступен только через SSH-туннель или отдельный ACL
- [ ] Docker Compose обновлён и работает
- [ ] Smoke-тесты пройдены
- [ ] Vault-заметка обновлена
- [ ] Handoff от всех ролей

## Зависимости

- Нет (самодостаточная задача)

## Риски

| Риск | Вероятность | Митигация |
|------|:-----------:|-----------|
| После смены bind сервисы не могут связаться друг с другом | Низкая | Docker networking позволяет localhost-доступ |
| Prometheus перестаёт собирать метрики | Низкая | Перенести scrape на 127.0.0.1 |
| Потеря удалённого доступа к метрикам | Средняя | Настроить SSH-туннель или VPN |
